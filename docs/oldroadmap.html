01

Overview

A modern cashless transport platform for Ilorin. Passengers tap an NFC card and money flows instantly from their linked bank account to the driver's OPay, PalmPay, GTBank — wherever they already receive money. The platform earns a small percentage per trip. No money is ever held.

An admin layer built on PostGIS and Mapbox gives operators a live map of all vehicles and gives investors a real-time proof of traction — trips ticking up, revenue flowing, Ilorin covered.

Core principles
Zero money held

Routing layer, not a wallet. Money moves directly from passenger's bank to driver's account via Moniepoint's NIP rails.

One bridge — Moniepoint

Single API for both collection and disbursement. One integration, every Nigerian account reachable.

Multi-account fallback

Passengers link multiple accounts in priority order. If Account 1 is empty, Account 2 is tried automatically.

Same app, two roles

One Flutter app for passengers and drivers. Role determined at registration.

Geospatial intelligence

Every terminal reports GPS coordinates. PostGIS powers live driver tracking, corridor analytics, and dead-zone detection — feeding both operations and investor demos.

04

Payment Flow

1 — Scanner tap

NFC scanner on Keke reads passenger card. Sends HTTP POST to your Go API over GSM.

POST /tap { "card_id": "ABC123", "terminal_id": "KEKE_001", "amount": 200, "lat": 8.4966, // pickup coords captured at tap "lng": 4.5426 }
2 — Identify & validate

API looks up passenger from card_id. Looks up driver from terminal_id. Validates both accounts are active.

3 — Fallback chain

API tries passenger's accounts in priority_order. Calls Moniepoint A2A debit on Account 1. If insufficient, tries Account 2. Continues until success or all exhausted.

4 — Moniepoint executes

Debits passenger ₦200, credits driver ₦190, platform keeps ₦10. Settles in under 5 seconds via NIP rails.

5 — Geo + commit

Trip record written with pickup_point geometry. Corridor stats updated. WebSocket broadcasts new dot position to admin map. Both users notified.

On failure — automatic rollback

PostgreSQL rolls back the entire transaction. Passenger balance untouched. No money lost. Scanner receives retry response.

Multi-account fallback
1.GTBank₦0 balanceskip
2.OPay₦450 — debit ₦200✓ paid
3.PalmPaynot reached—
Driver sees: "Payment successful"  ·  Passenger: "Paid from OPay · GTBank had insufficient funds"

Geospatial Layer NEW

PostGIS turns your existing PostgreSQL into a full geospatial database. Every scanner pings its coordinates every 30–60 seconds. Every tap records a pickup geometry. From that data you can answer questions no spreadsheet can.

What geospatial unlocks
Operations
Live driver positions, dead zones, breakdown detection
Analytics
Top corridors, demand heatmap, coverage growth
Investor demo
Live map + revenue ticker = proof of traction
Scanner GPS ping
// Scanner sends every 30–60 seconds POST /location { "terminal_id": "KEKE_001", "lat": 8.4966, "lng": 4.5426 } // Go handler updates two places: // 1. terminals.last_lat/lng (current position) // 2. terminal_locations table (full history) // 3. Broadcasts to /ws/map WebSocket
PostGIS power queries
-- All active terminals within 2km of a point SELECT t.id, t.vehicle_plate, t.last_lat, t.last_lng FROM terminals t WHERE ST_DWithin( ST_MakePoint(t.last_lng, t.last_lat)::geography, ST_MakePoint(4.5426, 8.4966)::geography, 2000 -- metres ); -- Trip density heatmap (last 24h) SELECT ST_SnapToGrid(pickup_point, 0.005) AS cell, COUNT(*) AS trip_count FROM trips WHERE tapped_at > NOW() - INTERVAL '24 hours' GROUP BY cell ORDER BY trip_count DESC;

What we're building
A cashless transport platform for Ilorin

One app that serves both passengers and drivers. Passengers link their bank accounts and tap to pay. Drivers receive money instantly to any Nigerian bank or wallet. The platform earns a small fee per transaction. No money is held — it flows directly from passenger to driver via Moniepoint's infrastructure.

Starting with Keke NAPEP on Ilorin's busiest corridors, expanding to BRT when the city is ready.

Core principles
Zero money held
The platform is a routing layer, not a wallet. Money moves directly from passenger's bank to driver's account. No CBN stored-value license required at this stage.
One bridge — Moniepoint
A single API handles both collection (from passenger's linked bank) and disbursement (to driver's any-bank account). One integration, every Nigerian account reachable via NIP rails.
Multi-account fallback
Passengers link multiple accounts with a priority order. If the primary account has insufficient funds, the next account is tried automatically. A seamless tap, always.
Same app, two roles
Passengers and drivers use the same Flutter app. Role is determined at registration. The UI surfaces different screens but the underlying auth and data model are unified.

Key backend decisions
Go for the API
Handles concurrent tap requests with low latency. Compiles to a single binary. Easy to deploy on a cheap VPS. Aligns with what you're already learning.
PostgreSQL transactions for safety
Every tap runs inside a DB transaction. If Moniepoint fails to pay the driver, the passenger's balance is rolled back automatically. No money is lost.
BEGIN TRANSACTION
deduct passenger balance
call Moniepoint API
if success → COMMIT + log trip
if fail → ROLLBACK (balance restored)
END
Idempotency on every payout
Every Moniepoint API call includes a unique reference (trip_id + timestamp). If a network glitch triggers a retry, Moniepoint detects the duplicate and pays only once.
